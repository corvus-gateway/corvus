# 인터넷에 공개한 셀프 호스팅 서비스를 안전하게 지키는 방법

서비스가 인터넷에서 접속할 수 있게 되면 몇 분 안에 스캔이 시작됩니다. 봇이 `/.env`,
`/wp-login.php`, `/.git/config`, 인기 있는 앱의 알려진 취약점, 기본 비밀번호를 시도합니다. 이
체크리스트는 어떤 도구를 쓰든 적용됩니다. 마지막 절에서는 Corvus가 각 항목을 어떻게 처리하는지
보여 줍니다.

## 1. 꼭 공개해야 하는 것만 공개하기

가장 안전한 서비스는 인터넷에서 닿을 수 없는 서비스입니다.

- **나와 가족만 쓰나요?** 전 세계에 여는 대신 VPN(WireGuard, Tailscale, Headscale) 뒤에 두세요.
  어떤 WAF도 아예 닿을 수 없는 것만큼 안전하지는 않습니다.
- **공개해야 하나요**(블로그, 쇼핑몰, 공유 링크, 여러 사용자가 쓰는 앱)? **80·443 포트만** 열고,
  리버스 프록시로 향하게 하세요. 데이터베이스, SSH, 관리용 포트를 직접 포워딩하지 마세요.
- **공인 IP가 없나요**(CGNAT, 모바일 회선)? 리버스 프록시에서 끝나는 터널(Cloudflare Tunnel,
  Pangolin, 또는 WireGuard를 쓰는 작은 VPS)을 사용하세요.

## 2. 모든 서비스 앞에 리버스 프록시 하나, 그리고 HTTPS

리버스 프록시가 80/443에서 요청을 받아 도메인마다 알맞은 앱으로 전달하므로, 앱은 인터넷에 직접
노출되지 않고 보안을 적용할 곳이 한 군데로 모입니다.

- 자동으로 갱신되는 인증서(Let's Encrypt)로 모든 곳에 HTTPS를 적용하세요. 모두 잘 동작하면
  HTTP를 HTTPS로 리디렉션하고 HSTS를 켜세요.
- 앱 자체는 공개 포트에 두지 마세요. 프록시가 쓰는 Docker 네트워크나 `127.0.0.1`에만 공개하세요.

## 3. 알려진 공격은 앱에 닿기 전에 차단하기

셀프 호스팅 앱을 노리는 공격은 대부분 자동화되어 있습니다. 같은 공격 경로와 페이로드를 모든 IP
주소에 보냅니다. 프록시에 있는 웹 애플리케이션 방화벽(WAF)이, 아직 패치하지 못했을 수도 있는
앱에 닿기 전에 이를 막아 줍니다.

- 잘 알려진 공격 경로와 페이로드(SQL 인젝션, 경로 탐색, 원격 코드 실행, `.env`나 `.git` 같은 유출
  파일)를 차단하세요.
- 쓰고 있는 앱의 새 취약점이 공개되면, 업데이트할 수 있을 때까지 **가상 패치**(해당 공격을
  차단하는 규칙)를 추가하세요.

## 4. 공격을 반복하는 IP 차단하기

차단된 요청 하나는 잡음이지만, 수백 개를 보내는 IP는 공격자이거나 스캐너입니다. 일정 시간
차단하고, 다시 오면 더 오래 차단하세요.

- 전통적인 구성: 프록시의 접근 로그를 읽는 fail2ban이나 CrowdSec.
- 스스로 잠기지 않도록 내 네트워크와 모니터링은 예외로 두세요.
- 공유 IP(통신사, 사무실)는 조심하세요. 영구히 차단하지 말고 시간을 정해 차단하세요.

## 5. 요청 속도 제한하기, 특히 로그인

Rate Limit은 비밀번호 추측과 스크래핑을 느리게 만듭니다. 로그인과 API 경로에는 더 엄격한 한도를
적용하고, 봇이 로그인 페이지를 계속 두드린다면 그 앞에 브라우저 챌린지를 두세요.

## 6. 관리 화면은 비공개로 유지하기

프록시, NAS, 공유기, 앱의 관리 화면은 공개 인터넷에 있으면 안 됩니다.

- LAN이나 VPN에서만 허용하고, 강한 비밀번호와 2단계 인증을 사용하세요.
- **Docker 함정:** ufw와 firewalld는 Docker가 공개한 포트(compose의 `ports:`)를 걸러 내지
  **않습니다**. `ufw status`에 닫힌 것으로 나오는 포트가 실제로는 열려 있을 수 있습니다. 관리용
  포트는 `127.0.0.1`이나 사설 주소에 공개하거나, `DOCKER-USER` 체인에서 걸러 내세요.

## 7. 업데이트, 백업, 관찰

- 앱과 프록시를 정기적으로 업데이트하고, 릴리스 알림을 구독하세요.
- 데이터**와** 프록시 설정을 백업하고, 복원을 한 번은 시험해 보세요.
- 가끔 트래픽을 살펴보세요. 어떤 호스트가 공격받는지, 어떤 IP가 차단되었는지, 앱이 어떤 오류를
  돌려주는지 확인하세요. 평소와 다른 일이 생기면 알림을 받으세요.

## Corvus가 처리하는 방식

[Corvus](../index.md)는 이런 보호 기능이 내장되어 있고 웹 콘솔에서 관리하는 리버스 프록시입니다.

| 체크리스트 항목 | Corvus에서 |
|---|---|
| 리버스 프록시와 HTTPS | [프록시 호스트](../proxy/proxy-hosts.md), [자동 갱신되는 Let's Encrypt](../proxy/certificates.md), HTTPS 강제와 HSTS |
| 알려진 공격 차단 | [기본으로 켜진 공격 경로 차단](../security/index.md), 요청 본문 검사, 가상 패치 템플릿 |
| 공격을 반복하는 IP 차단 | 차단 시간이 점점 늘어나고 예외 네트워크를 지원하는 [자동 차단](../security/bans.md), 로그 파싱 불필요 |
| Rate Limit과 봇 | [호스트별 Rate Limit](../security/bans.md#rate-limits), [브라우저 챌린지와 공격 대응 모드](../security/challenge.md) |
| 규칙과 차단 목록 | IP, 국가, 경로, 헤더, User-Agent 기준의 [보안 규칙](../security/rules.md), [URL에서 가져오는 차단 목록](../security/ip-lists.md) |
| 일부 사람만 쓰는 앱 | 호스트 앞의 [로그인 페이지](../security/login-page.md): PIN 하나, 또는 2단계 인증을 갖춘 사용자 |
| 비공개 콘솔 | 별도 포트, [접근 허용 네트워크, MFA, SSO](../operations/users.md) |
| 관찰 | [실시간 트래픽, 요청 로그](../operations/traffic.md), [알림](../operations/alerts.md), [백업](../operations/backup.md) |

그래도 첫 번째 항목은 대신할 수 없습니다. 나만 쓰는 서비스라면 VPN이 더 좋은 답입니다.

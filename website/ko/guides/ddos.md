# 셀프 호스팅 서버에서 트래픽 폭주와 DDoS 대응하기

"DDoS 방어"라는 말은 아주 다른 두 가지 문제를 가리킵니다. 어느 쪽인지 알아야 무엇이 도움이
되는지 알 수 있습니다.

## 두 종류의 폭주

| | 대용량 공격 (3/4계층) | 애플리케이션 계층 (7계층) |
|---|---|---|
| 내용 | 막대한 양의 패킷(UDP 플러드, SYN 플러드, 증폭 공격) | 정상처럼 보이는 많은 HTTP 요청: 페이지 로드, 검색, 로그인 |
| 가득 채우는 대상 | 내 인터넷 회선이나 업체의 네트워크 | 앱의 CPU, 데이터베이스, 워커 풀 |
| 내 서버가 막을 수 있나요? | **아니요.** 어떤 소프트웨어가 보기도 전에 이미 회선이 감당할 수 없는 트래픽입니다 | **네, 대부분** 앞에 둔 리버스 프록시로 막을 수 있습니다 |
| 도움이 되는 것 | 호스팅 업체의 DDoS 필터링, 또는 앞에 두는 CDN/프록시 서비스 | Rate Limit, 차단, 챌린지, 캐싱, 접속 대기열 |

그러니 어느 종류인지 밝히지 않고 "DDoS 방어"를 약속하는 셀프 호스팅 도구는 의심해 보세요.

## 애플리케이션 계층 대량 요청에 대응하기

1. **IP별 Rate Limit**은 클라이언트 하나가 사람이라면 보낼 리 없는 양을 보내지 못하게 합니다.
2. **자동 차단**은 한도나 공격 패턴에 계속 걸리는 IP를 걸러 냅니다.
3. 공격을 받는 동안 모든 방문자에게 거는 **브라우저 챌린지**(공격 대응 모드)는 실제 브라우저를
   쓰지 않는 봇을 막고, 사람은 1초쯤 뒤에 통과합니다. 초당 요청 수가 급증할 때 자동으로 켜지면
   가장 좋습니다.
4. **내 클라이언트는 허용하세요**(모니터링, 앱, API). 그래야 챌린지가 켜져 있는 동안에도 계속
   동작합니다.

## 실제 방문자가 몰릴 때

모든 폭주가 공격은 아닙니다. 출시, 티켓 판매, 화제가 된 글은 앱이 감당할 수 있는 것보다 많은 실제
방문자를 불러올 수 있습니다. 이들을 차단하는 것은 잘못입니다. **접속 대기열**은 앱이 처리할 수
있는 만큼만 방문자를 입장시키고 나머지는 순서대로 대기시키므로, 사이트가 모두에게 쓰러지는 대신
계속 쓸 수 있는 상태로 유지됩니다.

Corvus는 내 서버에서 동작하므로, 다른 셀프 호스팅 소프트웨어와 마찬가지로 대용량 공격을 흡수할
수는 없습니다. 그런 공격이 예상된다면 호스팅 업체의 DDoS 필터링이나 CDN을 앞에 두세요. Corvus는

오므로 그 뒤에서도 그대로 동작합니다.

# Corvus는 이렇게 동작합니다

## 그림 하나로 보는 원리

Corvus가 없으면 방문자가 웹 서버에 바로 접속합니다.

```text
방문자 ──► :80 / :443  내 웹 서버
```

Corvus를 두면 80·443 포트로 들어오는 요청을 Corvus가 대신 받아서, 검사한 뒤 원래 가야 할 웹 서버로
넘겨 줍니다.

```text
                         ┌──────────────────────────────┐
방문자 ──► :80 / :443 ──►│ Corvus                       │──► 블로그        (컨테이너, 2368 포트)
                         │  · HTTPS 인증서              │──► Nextcloud     (컨테이너, 80 포트)
                         │  · 공격 차단, 봇 차단        │──► 기존 웹사이트 (이 서버, 8080 포트)
                         │  · 접속 대기열, 트래픽 관제  │
                         └──────────────────────────────┘
                              관리 콘솔 :9443
```

방문자는 여전히 `https://blog.example.com`으로 접속하고, Corvus 뒤의 포트 번호는 보지 못합니다. 이런
프로그램을 **리버스 프록시**라고 부릅니다.

## 이 문서에서 쓰는 말

| 용어 | 뜻 |
|---|---|
| **게이트웨이** | 80·443 포트에서 방문자를 맞는 Corvus의 부분입니다. |
| **프록시 호스트** | Corvus에 만드는 규칙 하나입니다. "이 도메인으로 온 요청은 저 웹 서버로". 웹사이트나 앱마다 하나씩 만듭니다. |
| **Corvus 뒤의 서비스**, **전달 대상**, **업스트림**, **백엔드** | 실제로 페이지를 만드는 웹 서버나 앱입니다. 예: WordPress 컨테이너, 이미 쓰고 있던 nginx. Corvus가 요청을 넘겨 주고 응답을 방문자에게 돌려줍니다. |
| **전달 대상 호스트 / 포트** | *Corvus에서* 그 서비스에 닿는 주소입니다. 컨테이너 이름, IP 주소, 또는 같은 서버의 서비스라면 `127.0.0.1`. |
| **관리 콘솔** | 이 모든 것을 설정하는 웹 화면으로, 9443 포트에 있습니다. 방문자는 쓰지 않습니다. |

한 포트는 한 번에 프로그램 하나만 쓸 수 있습니다. Corvus가 80·443을 쓰므로, Corvus 뒤의 서비스는 다른
포트에서(또는 Docker 안에서만) 동작하고 Corvus가 그쪽으로 요청을 넘깁니다.

## 이미 80·443 포트를 쓰는 웹 서버가 있어요 { #i-already-have-a-web-server-on-ports-80-and-443 }

웹 서버를 다른 포트로 옮기고, Corvus를 80·443으로 띄운 다음, 프록시 호스트를 새 포트로 연결하면 됩니다.
사이트 내용은 그대로이고, 웹 서버가 듣는 포트만 바뀝니다.

### 1. 웹 서버를 다른 포트로 옮기기

비어 있는 포트를 하나 고릅니다. 예: **8080**. 이제부터 웹 서버는 평범한 HTTP만 제공하면 됩니다. HTTPS와
인증서는 Corvus가 맡습니다.

=== "nginx"

    사이트 설정의 `listen` 줄을 바꿉니다.

    ```nginx
    server {
        listen 8080;            # 원래: listen 80;
        # "listen 443 ssl" server 블록은 지우거나 다른 포트로 옮깁니다
        server_name example.com;
        ...
    }
    ```

    그다음 `sudo nginx -t && sudo systemctl reload nginx`를 실행합니다.

=== "Apache"

    `ports.conf`에서 `Listen 80`을 `Listen 8080`으로 바꾸고 `Listen 443`은 지웁니다. 가상 호스트의
    `<VirtualHost *:80>`도 `<VirtualHost *:8080>`으로 바꿉니다. 그다음
    `sudo apachectl configtest && sudo systemctl reload apache2`를 실행합니다.

=== "Docker 컨테이너"

    그 컨테이너의 `docker-compose.yml`에서 공개 포트를 바꿉니다. 예: `'80:80'` 대신 `'8080:80'`, 그리고
    `'443:443'`은 지웁니다. 그다음 `docker compose up -d`를 실행합니다.

    더 좋은 방법은 포트를 아예 공개하지 않고, Corvus와 같은 Docker 네트워크에 컨테이너를 넣는 것입니다.
    [Corvus를 다른 컨테이너와 연결하기](first-host.md#before-you-start)를 참고하세요.

새 포트에서 사이트가 응답하는지 확인합니다: `curl -I http://127.0.0.1:8080`

!!! warning "웹 서버가 Docker에서 오는 연결을 받아야 합니다"
    Corvus는 컨테이너 안에서 동작하므로 Docker를 거쳐 `127.0.0.1:8080`에 접속합니다. 웹 서버가
    `127.0.0.1`에서만 듣고 있다면(예: `listen 127.0.0.1:8080;`) 모든 주소에서 듣도록 바꾸고(`listen 8080;`)
    8080 포트는 방화벽으로 막아 두세요. 또는 Corvus를
    [호스트 네트워크](install.md#run-it-with-host-networking-optional)로 실행합니다.

### 2. Corvus 설치하고 시작하기

이제 80·443 포트가 비었습니다. [설치](install.md)를 따라 하세요.

### 3. 내 사이트용 프록시 호스트 만들기

관리 콘솔에서 **프록시 호스트 → 프록시 호스트 추가**를 누릅니다.

| 항목 | 값 |
|---|---|
| 도메인 | `example.com` (쓰고 있다면 `www.example.com`도) |
| 프로토콜 | `http` |
| 호스트 / IP | `127.0.0.1` (컨테이너 안에서는 *이 서버*를 뜻합니다) |
| 포트 | `8080` |

**TLS** 섹션에서 Let's Encrypt 인증서를 요청하고 **HTTPS로 강제 이동**을 켠 뒤 저장합니다. 이제 사이트가
Corvus를 거쳐 서비스됩니다. 자세한 내용은 [첫 프록시 호스트](first-host.md)를 참고하세요.

### 잘 안 될 때

- **502 Bad Gateway**: Corvus가 8080 포트에 닿지 못합니다. 위의 주의 사항과
  [문제 해결](../reference/troubleshooting.md)을 확인하세요.
- **리디렉션 루프**: 웹 서버나 앱이 스스로 HTTPS로 리디렉션하고 있습니다. 그 일은 Corvus가 이미 하므로
  앱의 HTTPS 리디렉션을 끄거나, 앱에 프록시 뒤에 있다고 알려 주세요(앱은 `X-Forwarded-Proto: https`를
  받습니다).
- **링크가 이상하거나 혼합 콘텐츠 경고**: 앱의 사이트 주소를 `https://example.com`으로 설정합니다
  (WordPress: *설정 → 일반*).
